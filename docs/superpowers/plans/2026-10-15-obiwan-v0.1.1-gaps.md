## Task 1: Record schema version check and migration seam

**Files:** `obiwan/obiwan/record/__init__.py`, `obiwan/obiwan/record/schema.py`, `obiwan/tests/test_record.py`.

Today `Record.__init__` runs `executescript(SCHEMA + TRIGGERS)` then writes `PRAGMA user_version = SCHEMA_VERSION`
unconditionally, never reading it. Change it to:

1. Read `PRAGMA user_version` **before** applying the schema.
2. `0` → fresh file: apply schema + triggers, set `SCHEMA_VERSION`.
3. `< SCHEMA_VERSION` → apply schema + triggers (additive `CREATE ... IF NOT EXISTS`), then run each migration step
   from `found+1` to `SCHEMA_VERSION` from a `MIGRATIONS: dict[int, str]` in `schema.py` (empty today; Task 5 adds one),
   then set `SCHEMA_VERSION`. Do it inside one transaction where SQLite allows; journal a `schema_migrated` event with
   `from` and `to`.
4. `> SCHEMA_VERSION` → raise `RuntimeError` naming both numbers ("record is schema N, this build understands M")
   and do not modify the file.

Keep `SCHEMA_VERSION = 1` in this task. Tests: fresh file gets version 1; a file at version 1 reopens with no event;
a file set to `SCHEMA_VERSION + 1` raises and its `user_version` is unchanged afterwards; a migration step is applied
when opening an older file (monkeypatch `SCHEMA_VERSION`/`MIGRATIONS` to simulate 1 → 2).

## Task 2: Symlink containment for every source read

**Files:** `obiwan/obiwan/scanner.py`, `obiwan/obiwan/worker.py`, `obiwan/obiwan/inbox.py`, tests in
`obiwan/tests/test_scanner.py`, `test_worker.py`, `test_inbox.py`.

A symlink inside a root (or inbox) can point outside it; today it is followed. Add one helper, e.g.
`obiwan/obiwan/core/paths.py: is_contained(path: Path, root: Path) -> bool` comparing `path.resolve()` with
`root.resolve()` via `Path.is_relative_to` (catch `OSError`/`RuntimeError` from resolve → not contained).

- `discover`: a file whose resolved path escapes the root is skipped and counted in a new
  `RootReport.skipped_outside` (int) plus an entry in `errors` naming the relative path. A symlink whose target is
  inside the root is still accepted (it is an ordinary file under the root).
- `scan_root`: re-check containment immediately before stat + hash (a file swapped for a symlink after discovery).
- `worker.process_item`: check containment of `root_path / sighting.path` before hashing/extracting; on escape raise
  a dedicated exception (the work row fails with that reason; nothing is read).
- `inbox`: a pending inbox entry that escapes the inbox is moved to `failed/` with reason, never read. The inbox
  itself is writable, so moving the link (not its target) is allowed: use the link path, never the resolved one.
- Directory symlinks: Python 3.12 `rglob` does not recurse into symlinked directories; add a test that a symlinked
  directory pointing outside contributes no files.

Tests create symlinks with `os.symlink` and `pytest.skip` on `OSError`.

## Task 4: Per-document projection repair through an `index` work item

**Files:** `obiwan/obiwan/work.py`, `obiwan/obiwan/worker.py`, `obiwan/obiwan/record/__init__.py`,
`obiwan/obiwan/service.py`, tests in `test_work.py`, `test_worker.py`, `test_service.py`.

Today a document whose chunks are not `current` in `projection` is repaired only by a global `/reindex`.

- `WorkQueue.requeue(kind, target, *, now) -> bool`: insert as pending, or if a row exists in state `done` or
  `failed`, reset it to `pending` with `attempts = 0`, `last_error = NULL`, `next_attempt_at = now`. A `pending` or
  `leased` row is left alone. (`enqueue` keeps its current INSERT OR IGNORE semantics for `extract`.)
- `Record.documents_needing_index() -> list[str]` (doc_ids): latest, live (not tombstoned) documents that have
  chunks, where any chunk has no `fts` projection row or a row whose state is not `current`. Reuse `_LATEST_LIVE`.
- `worker.process_item`: new kind `"index"`: load the document and its stored chunks and call
  `projection.index_document`. Never read a source file. A document with no chunks is an error (the extract item
  owns that case).
- `Service.scan`: before `drain`, sweep `documents_needing_index()` and `requeue("index", doc_id)` each; report the
  count as `repairs_enqueued` in the scan result. The sweep runs under the existing maintenance lock (scan already
  takes it in `web.py`), so it cannot interleave with `/reindex`.
- Tests: corrupt one document's projection state (set its rows `stale`, delete its FTS rows) → after `scan`, that
  document is searchable again, its rows are `current`, other documents' `built_at` did not change, and no source
  file was read (monkeypatch `extract_text` to raise). A second break of the same document is repaired again
  (proves `requeue` resets `done`).

## Task 5: Commander excludes a permanently failed document

**Files:** `obiwan/obiwan/record/schema.py`, `obiwan/obiwan/record/__init__.py`, `obiwan/obiwan/service.py`,
`obiwan/obiwan/web.py`, `obiwan/obiwan/cli.py`, tests in `test_record.py`, `test_service.py`, `test_web.py`,
`test_cli.py`; docs in Task 6.

Decision (Commander, 2026-10-15): a commander-only power excludes a document version that failed extraction, with a
reason. Coverage reports it and may become complete. A changed file produces a new version, which is tried fresh.

- Schema: new append-only table `exclusions(id INTEGER PRIMARY KEY, doc_id TEXT NOT NULL REFERENCES documents(doc_id),
  reason TEXT NOT NULL, ordered_by TEXT NOT NULL, created_at TEXT NOT NULL, UNIQUE(doc_id))`, added to `APPEND_ONLY`.
  `SCHEMA_VERSION = 2`; `MIGRATIONS[2]` is the `CREATE TABLE IF NOT EXISTS exclusions ...` (plus its triggers), so a
  live version-1 file migrates on open (Task 1 seam). New power `"exclude"` in `_COMMANDER` only.
- `Record.add_exclusion(...)`, `Record.exclusion_for(doc_id)`.
- `Service.exclude(*, subject_id, reason, role)`: target is the latest live version of `subject_id`; refuse
  (`ValueError`) unless that version has no chunks and its `extract` work row is `failed`; refuse an empty reason;
  write the exclusion and an `exclusion` event in one transaction.
- Route: extend the existing commander route `POST /confirm` with `"action": "exclude"` and a required `reason`,
  matching the `forget` shape; guard with power `"exclude"`. Writer and reader tokens get 403 (test both).
- CLI: `obiwan exclude <subject_id> --reason R` using `OBIWAN_COMMANDER_TOKEN`, same pattern as `forget`.
- Coverage (`Record.coverage_counts`, `Service.coverage`): add `documents_excluded`. An excluded latest version
  counts neither as failed nor as un-indexed. `complete` becomes: every latest live non-excluded document indexed,
  no pending work, no failed work **whose target is a latest live non-excluded document**, all roots reachable.
  A failed `extract` row for a superseded version therefore no longer pins `complete` (it did before; add a test).
  `/status` keeps listing every failed work row, raw, so nothing is hidden.
- Tests: fail one document terminally → `complete` false, `documents_failed` 1; exclude it → `complete` true,
  `documents_excluded` 1, `documents_failed` 0, event journaled; change the file and scan → the new version is not
  excluded and is extracted; exclude refused for an indexed document, for a missing reason, for writer role; a v1
  record file (create with `SCHEMA_VERSION=1` schema, no exclusions table) opens, migrates to 2, and has the table.
